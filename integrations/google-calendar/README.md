# Внутренний калькулятор → Google Calendar

Проверено 4 сентября 2026: Calendar API включён, Web OAuth-клиент создан, рабочий аккаунт добавлен в Testing. Одна обезличенная запись успешно отправлена из локального `/calc`, подтверждены заголовок нового клиента, смета и длительность 1 час. Production ещё не обновлён; перед сборкой Pages требуется Actions variable ниже.

Только `/calc`: кнопка создаёт событие непосредственно через Google Calendar API в календаре `cleanlifesochi@gmail.com`. Публичные калькуляторы и существующий Apps Script → amoCRM не меняются. Внутренняя кнопка больше не создаёт сделку amoCRM и строку Google Forms; соответственно, этот путь сам по себе не возвращает оплаты в Метрику.

## Поведение

- Название: `Влажная 30 кв.м.`; флажок «Новый клиент» добавляет ` - новый клиент`.
- Обязательны выбранные услуги, телефон, дата и время. Телефоны РФ с `+7`, `8` и десятью цифрами поддерживаются.
- Начало — выбранное время в `Europe/Moscow`, конец — строго через один час (решение пользователя).
- Описание содержит смету, итоговую цену, контакты, адрес, пожелания, отметку частного дома и заявленный источник. Маржа, себестоимость и другая экономика не передаются.
- Клиент не добавляется гостем; приглашения и напоминания не создаются.
- Успех показывается только после ответа API с активным событием и ожидаемым ID. Предоставляется ссылка на запись.
- На время отправки отключён сброс. Повторная попытка в той же вкладке использует неизменные ID и данные, при HTTP 409 читается уже созданное событие. После успеха кнопка заблокирована до «Сбросить всё». Изменение полей после отправки не обновляет событие автоматически.
- При перезагрузке страницы/сбросе состояние попытки теряется: при неясном результате сначала проверить календарь, а не заводить новый заказ.

## Однократное подключение

1. Войти в Google Cloud именно под `cleanlifesochi@gmail.com`. Личный аккаунт владельца не использовать.
2. Создать/выбрать проект для Blesk23; включить **Google Calendar API**. Платёжный аккаунт для этой интеграции не подключать.
3. Настроить Google Auth Platform / OAuth consent: приложение внутреннего калькулятора. Для личного Gmail используется аудитория External; в режиме Testing добавить рабочий аккаунт в Test users. Согласия и доступы подтверждает владелец.
4. Создать OAuth Client ID типа **Web application**. Authorized JavaScript origins:
   - `https://www.blesk23.ru`
   - `https://blesk23.ru`
   - `http://localhost:5173` только для локальной проверки.
5. В локальный `.env.local` добавить `VITE_GOOGLE_CALENDAR_CLIENT_ID=<Client ID>`; для GitHub Pages — одноимённую **Actions variable** (workflow уже передаёт её в сборку). Это публичный идентификатор, не client secret. Client secret и refresh token приложению не нужны.
6. Пересобрать сайт. Открыть `/calc`, заполнить тестовые данные и нажать отправку. В Google выбрать рабочий аккаунт и подтвердить разрешение `calendar.events`. Google проверяет право записи именно в указанный календарь — никакого fallback на `primary` нет.
7. После отдельного разрешения на тестовую запись проверить событие: календарь, заголовок с флажком и без, местное время, длительность 60 минут, смета. Не удалять тестовое событие без указания владельца.

OAuth access token находится только в памяти страницы и не записывается в Supabase, Google Forms или localStorage. PIN внутреннего калькулятора — только UI-ограничение, не защита Calendar API. Доступ проверяет Google. OAuth-загрузка выполняется только внутри внутреннего калькулятора, не на публичных страницах.

До заполнения Client ID кнопка явно показывает «Google Календарь ещё не подключён» и не выполняет ложную отправку. Не публиковать такую сборку вместо действующей без согласования незавершённого подключения.

Документация: [Google Identity token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model), [Calendar events.insert](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert).
