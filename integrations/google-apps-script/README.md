# Google Forms → amoCRM

Исходник привязанной к таблице `Blesk23 (Ответы)` интеграции.

## Что делает

- запускается по новой строке Google Forms;
- разбирает блок `Атрибуция` из сообщения;
- заполняет технические колонки F:Z;
- ищет контакт в amoCRM по нормализованному телефону;
- если у контакта есть заявка в «Неразобранном», принимает её и дополняет вместо создания дубля;
- иначе дополняет последнюю открытую сделку ранней стадии за последние 30 дней;
- если контакт из «Неразобранного» ещё недоступен обычному поиску amoCRM, отправляет заявку через `POST /api/v4/leads/complex` со штатным контролем дублей по телефону;
- после первой заявки через `POST /api/v4/leads/complex` amoCRM автоматически создаёт источник интеграции и показывает его в настройках контроля дублей;
- создаёт новый контакт и новую сделку только при отсутствии подходящей активной сделки;
- не объединяет новую заявку с назначенной, выполненной или закрытой уборкой;
- назначает Ферузу ответственной за принятую, дополненную или новую сделку;
- заполняет UTM, `yclid`, ClientID Метрики, посадочные страницы и услугу;
- записывает клики по телефону как технические строки без создания сделки;
- записывает клики по WhatsApp, Telegram и MAX вместе с UTM, `yclid` и ClientID до ухода посетителя с сайта;
- сопоставляет единственный новый чат с кликом того же мессенджера в 20-минутном окне и переносит атрибуцию в сделку;
- принимает вебхук входящих сообщений Wazzup и добавляет найденный в тексте российский номер (`+7`, `7` или `8`) в контакт;
- создаёт новую публичную заявку калькулятора как форму в «Неразобранном», назначая Ферузу при принятии;
- если телефон калькулятора уже связан с «Неразобранным» или ранней активной сделкой, дополняет её расчётом вместо создания дубля;
- для заявки из внутреннего `/calc` подставляет атрибуцию, только если за 15 минут найден ровно один незанятый `phone_click`;
- помечает такую атрибуцию как эвристическую, а при нуле или нескольких кликах не приписывает сделке чужие UTM;
- добавляет расчёт и всю атрибуцию в примечание существующей сделки без потери старых данных;
- не создаёт задачи и напоминания: Феруза работает только с воронкой и данными сделки;
- каждые 15 минут заполняет операционные поля по этапам сделки без блокировки переходов;
- для квалифицированных этапов заполняет «Квалификация», если поле пустое;
- определяет «Новый/Повторный» по предыдущим успешно закрытым сделкам контакта;
- при переходе в «Успешно реализовано» ставит «Оплачено» и дату оплаты по времени закрытия сделки;
- записывает `amo_lead_id`, статус синхронизации и ошибку обратно в таблицу.
- каждые 15 минут проверяет изменения сделок amoCRM за доступное Метрике 21-дневное окно;
- возвращает в Метрику цели `qualified_lead`, `booking`, `service_completed`, `paid_order` и `paid_new_client`;
- передаёт выручку в рублях для оплаченных заказов и отдельно выделяет новых клиентов;
- связывает офлайн-конверсию с визитом по `ClientID` и/или `yclid`;
- ведёт отдельный лист `Метрика — конверсии` с ID сделки, целью, загрузкой и защитой от повторов.

## Секрет

Токен не хранится в репозитории. В свойствах проекта Apps Script должен быть ключ:

```text
AMO_LONG_LIVED_TOKEN=<токен приватной интеграции amoCRM>
METRIKA_OAUTH_TOKEN=<OAuth-токен с правами metrika:read и metrika:offline_data; для создания целей дополнительно metrika:write>
WAZZUP_WEBHOOK_SECRET=<случайный секрет в URL вебхука; создаётся setupWazzupWebhookSecret()>
WAZZUP_API_KEY=<ключ из Wazzup → Интеграция с CRM → Дополнительно>
```

После установки токена один раз запускается `setupIntegration()`. Функция проверяет соединение и создаёт установленный триггер `handleFormSubmit`.

После обновления операционной автоматизации один раз запускается `setupOperationalAutomation()`. Она удаляет старый одноимённый триггер, создаёт проверку каждые 15 минут и сразу заполняет пропущенные поля в недавних сделках.

После установки токена Метрики один раз запускается `setupMetrikaIntegration()`. Она проверяет счётчик и наличие пяти бизнес-целей, создаёт журнал загрузок и триггер `syncAmoConversionsToMetrika` каждые 15 минут. Перед первой реальной загрузкой можно выполнить `previewMetrikaConversions()`.

После добавления интерактивных блоков сайта и выдачи токену права `metrika:write` запускается `setupSiteEngagementGoals()`. Функция через официальный API Метрики создаёт только отсутствующие JS-цели и не дублирует уже настроенные. Для блока отзывов это `reviews_open`, `review_card_click`, `reviews_all_click` и `review_create_click`.

Для распознавания телефона, который клиент присылает в MAX/Telegram/WhatsApp, проект Apps Script публикуется как Web App с выполнением от владельца. Затем в свойства добавляется `WAZZUP_API_KEY` и один раз запускается `setupWazzupUserApiWebhook()`. Функция подписывает пользовательский API v3 на входящие сообщения и статусы, а URL защищает параметром `WAZZUP_WEBHOOK_SECRET`. Обработчик понимает как формат пользовательского API v3, так и партнёрского API v2. Повторный номер не дублируется: `8XXXXXXXXXX`, `7XXXXXXXXXX` и `+7XXXXXXXXXX` нормализуются к одному значению `+7XXXXXXXXXX`.

Supabase для атрибуции не требуется: браузер хранит first-touch параметры 90 дней в `localStorage`, а перед переходом в мессенджер сразу отправляет их в техническую строку Google Forms. Таблица остаётся серверным журналом кликов; amoCRM получает атрибуцию после однозначного сопоставления клика и беседы.

`paid_order` отправляется для любого оплаченного заказа. `paid_new_client` отправляется дополнительно только тогда, когда в поле amoCRM «Тип клиента» явно указано, что клиент новый. Если `ClientID` и `yclid` отсутствуют, сделка не загружается: без этих идентификаторов Метрика не сможет достоверно связать её с рекламным визитом.

Во внешней интеграции amoCRM должна быть включена опция **Контроль дублей**. Источник внешней интеграции нельзя создать через API без JS-виджета: amoCRM добавит его автоматически после первой заявки через `POST /api/v4/leads/complex`. После контролируемого теста для этого источника в воронке настраиваются: сравнение по телефону, поиск в «Неразобранном» и ранних активных стадиях, обновление самой новой сделки и дополнение данными входящей заявки.

Для карточки внешней интеграции amoCRM подготовлен файл `assets/amo-integration-logo.png` точного размера 400×272 px.

Существующие строки таблицы должны иметь статус `historical_existing`, чтобы интеграция не создала по ним повторные сделки. Повтор конкретной строки выполняется вручную через `retryRow(<номер>)`.
