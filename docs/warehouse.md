# Склад `/sklad`

Закрытый склад Адлер / Сочи. Страница не связана с публичным меню, robots.txt или sitemap. Пререндер содержит `noindex, nofollow, noarchive`; на маршруте выключены Метрика и автоматический трекинг форм.

## Использование

Введите имя сотрудника и общий код. Сессия действует 12 часов в текущей вкладке. Имя в журнале указывается самим сотрудником, это не персональная учётная запись.

- Факт `Не посчитано` отличается от 0. Перед движением по такой позиции внесите известный фактический остаток через инвентаризацию, включая явный 0 для отсутствующих позиций.
- Поступление добавляет количество, списание уменьшает его. Перемещение списывает с выбранного склада и добавляет в другой. Для перемещения должны быть известны оба остатка.
- Инвентаризация заменяет только заполненные количества. Пустые строки не меняются. Можно посчитать одну позицию или несколько сразу.
- Нажмите эталон для изменения желаемого остатка. Столбец «Эталон» — норма склада (для техники это фото-список), отдельно от факта. Фильтр «Эталон техники» оставляет только категорию «Техника». Раздел «К пополнению» содержит только известные положительные дефициты.
- Если в примечании есть «ремонт», в строке виден бейдж «В ремонте». Количество при этом остаётся: техника всё ещё принадлежит компании.
- «Примечание» меняет только текст примечания (`annotate`) и не трогает факт и эталон. Чтобы отметить ремонт, допишите «В ремонте.» к уже существующему тексту — кнопка в форме делает это сама. Нужны основание операции и новый текст примечания (до 1000 символов, пустая строка очищает примечание).
- «Удалить» безвозвратно убирает позицию из каталога (`delete`). Это не списание: остаток никуда не переносится. Нужны основание и подтверждение. Повтор той же операции безопасен. После инвентаризации так убирают непосчитанные заглушки, например «Гель для чистки унитазов» и «Фильтр пластиковый для пылесоса». Ремонтные пометки для «Пылесос T8», «Парогенератор SC4» и «Парогенератор SC2» ставьте через «Примечание», не через удаление.
- «Позиция» добавляет карточку с непосчитанными остатками. CSV выгружает весь каталог и оба склада.
- Любая операция требует комментарий. История показывает последние 500 документов; база сохраняет все документы без удаления.
- «Обновить» получает текущие серверные остатки. При конфликте версий обновите данные и проверьте количество перед повторным проведением.
- При неизвестном результате сетевого запроса повторите через «Проверить / повторить». ID операции сохраняется в sessionStorage и переживает перезагрузку текущей вкладки. После перезагрузки есть кнопка проверки предыдущей операции. Не создавайте повторный документ в другой вкладке, пока не выяснен результат первого.

## Развёртывание

Склад использует отдельные переменные `VITE_WAREHOUSE_SUPABASE_URL` и `VITE_WAREHOUSE_SUPABASE_KEY` (публичный publishable key). Он не меняет подключение калькулятора. Активный проект склада: `bpbojrwsvbffmraqvcbi`.

Выполните по порядку в SQL Editor нужного проекта: `supabase/migrations/20260918120000_warehouse.sql`, затем `supabase/migrations/20260924120000_warehouse_delete_annotate.sql`. Вторая миграция заменяет `sklad_command` (те же аргументы) и добавляет виды `delete` и `annotate`. Повторный запуск второй миграции безопасен. Схема `sklad_private` не доступна anon/authenticated. Четыре публичные RPC проверяют сессию; изменения сериализуются блокировкой строки состояния и проверкой revision, документы имеют уникальный UUID для безопасных повторов. Удаление и правка примечания идут только через эти RPC, не прямым UPDATE таблицы.

Код хранится только в приватной серверной таблице `sklad_private.config` как bcrypt-хеш. Его установка выполняется администратором отдельно от миграции. Не коммитьте код, его хеш, сессии или начальные рабочие остатки в публичный репозиторий. Начальные остатки загружаются отдельно, однократно при revision=0. Исходный JSON сохранён локально вне репозитория.

Ограничение общего короткого кода: это доступ для доверенной команды; имя сотрудника не проверяется. Вход ограничен десятью запросами в минуту на весь склад. Прямая выдача таблиц запрещена, локальный кэш остатков отсутствует. Данные хранятся на сервере, поэтому необходим интернет.

## Проверки

- `supabase/tests/warehouse.sql`: реальные транзакционные тесты с `ROLLBACK`, без сохранения тестовых остатков или документов.
- `src/test/warehouse*.test.*`: количества, неизвестные остатки, доступ, повтор операции и восстановление после перезагрузки.
- Общие проверки проекта: typecheck, lint, Vitest, Vite build и prerender.

Для резервной копии данных используйте административный экспорт схемы sklad_private; CSV в интерфейсе содержит текущий каталог и не заменяет резервную копию полного журнала.
